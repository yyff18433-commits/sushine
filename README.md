# Sushine · 食物手账（前端页面骨架）

> 大规模软件系统 · 组员 4 交付物：**前端页面开发（页面骨架）**
> 设计来源：`寿司list-UI-交付`（10 屏高保真静态稿 + 视觉规范与组件库）
> 全部数据写死模拟，不需要后端。

**在线访问**：https://kk123-arch.github.io/sushine/

> 静态站点没有 Node 后端，AI 写备注 / 追问会降级为本地规则，看图识别退化为本地估算。
> 要体验完整的真实 AI，请在本地用 `npm run dev` 运行（见「部署说明.md」）。

## 1. 技术栈

| 项 | 选择 | 说明 |
| --- | --- | --- |
| 框架 | Vue 3（`<script setup>`） | 组合式 API，单文件组件 |
| 构建 | Vite 6 | 秒级热更新、按页面自动分包 |
| 路由 | Vue Router 4（hash 模式） | 构建产物可直接双击 `dist/index.html` 演示 |
| 样式 | 原生 CSS + CSS 变量（Design Token） | 不引 UI 库，保证 1:1 还原设计稿 |
| 状态 | `reactive` 极简 store | 不引 Pinia，减少依赖 |

**无第三方 UI 组件库、无网络字体**（沿用设计规范「全部走系统字体，首屏零等待」）。

## 2. 运行

```bash
cd sushine
npm install
npm run dev      # 开发预览 http://localhost:5173
npm run build    # 产出 dist/（相对路径，可直接本地打开）
npm run preview  # 预览构建产物
```

> 建议浏览器开启手机模拟（390 × 844）。桌面端宽度 ≥ 900px 时会自动套上手机外壳居中显示。

## 5. 设计还原要点

- **色彩**：陶土橘 `#D9885F` 为唯一强调色，一屏只出现在主按钮 / 当天日期上；纸底 `#FBF6EE`、卡片 `#FFFDF9`，不用纯白大面积铺底。
- **圆角**：8 / 14 / 16 / 18 / 20 / 24 / 28 / 36 / 999，随元素变大而更圆。
- **间距**：全部 4 的倍数；页面左右留白 20、卡片内边距 13、卡片间距 18、区块间距 28。
- **阴影**：每层都 = 2–4px 硬边（纸的厚度）+ 大范围柔光，禁止纯柔光。
- **纸纹**：`feTurbulence` 噪点，透明度 3.5%，铺在机身与卡片层，不压文字（见 `base.css` 的 `.phone::after`）。
- **字体**：不加载第三方字体；手写体 `STKaiti` 只用于 logo / 贴纸文案。
- **Token 对照**：设计稿 `color/or/500 → --or`、`radius/card → 24px`、`space/card-gap → 18px`，全部落在 `styles/tokens.css`，改一处即可全局换肤。

### 贴纸是怎么「生成」的

没有接后端模型，但也不是简单裁个圆 —— 是两条 Canvas 流水线：

1. `utils/cartoonify.js`：降采样 → 模糊放大（抹掉细节）→ 提饱和 → 色阶量化（8 级平涂）→ Sobel 边缘叠一层淡描边，得到「手绘插画」质感。
2. `utils/dieCut.js`：沿边缘生成一条带随机抖动的闭合曲线，填白色做**模切白边**，再把画面裁进内圈，输出**透明背景 PNG** —— 视觉上就像从贴纸册上撕下来的一张。

旧记录在 App 启动时会自动补做一次同样的处理（结果随 `entries` 持久化），保证首页不会出现「真实照片 + 插画贴纸」混排。

## 7. 响应式适配（对应组员 6 的「不同屏幕尺寸兼容性测试」）

原来的做法是「390×844 手机壳居中摆在电脑屏幕上」——窗口一变就被裁，也确实不算响应式。现在改成**三档真实响应式布局**，同一套代码、同一套设计语言：

| 断点 | 形态 | 说明 |
| --- | --- | --- |
| `< 768px` | 手机形态 | 全屏应用，模拟状态栏 + 底部悬浮 Tabbar + 中央凸起快门 |
| `768 – 1199px` | 平板形态 | 左侧 244px 竖向导航栏（品牌 + 导航 + 拍一张按钮），内容单列，自适应宽度 |
| `≥ 1200px` | 桌面形态 | 左栏导航 + 居中内容区（940→1080px），首页双列卡片、周报双列餐点、月历左右分栏 |

关键实现：

- **导航形态切换**：`STabBar` 同一份 DOM，小屏是底部 Tabbar，≥768px 变成左侧栏（`flex-direction: column`），并显示品牌区与「拍一张」文字按钮。
- **内容区**：`.page` 在小屏全宽，大屏 `max-width: 940/1080px` 居中，视觉上不会出现「一行字拉到 1900px」。
- **栅格流式化**：首页卡片 `repeat(2, 1fr)`、周报餐点双列、贴纸墙 `auto-fill minmax(140px, 1fr)`、月历左侧日历右侧数据。
- **聚焦流程页**（拍照 / 贴纸生成 / 贴纸信息 / 编辑）大屏限制在 560–660px 的居中工作区，避免图片被拉得过大。
- **状态栏**只在 `< 768px` 显示（桌面浏览器里画一个假 iOS 状态栏没有意义）。

实测断点行为（用 emulation 逐档验证）：

| 视口 | 导航 | 内容区 | 首页流 |
| --- | --- | --- | --- |
| 390×844 | 底部 Tabbar | 390 全宽 | 单列 |
| 768×1024 | 左侧栏 244 | 524 | 单列 |
| 1024×768 | 左侧栏 244 | 780 | 双列 |
| 1280×800 | 左侧栏 244 | 940（居中） | 双列 |
| 1920×1080 | 左侧栏 244 | 1080（居中） | 双列 |

## 8. 为什么之前「浏览器 100% 显示不全」，现在为什么不会

原因：桌面端把机身**硬编码成 `height: 844px`**，而浏览器窗口可视高度常常只有 700–800px，机身比窗口高，`overflow: hidden` 就把上下裁掉了。

修复：
1. 大屏不再模拟手机壳，直接 `height: 100dvh` 铺满窗口，内容区自己滚动。
2. 拍照页 / 贴纸生成 / 贴纸信息原本是「按 844px 绝对定位」的，改成 flex 流式布局，底部操作栏用 `position: sticky` 吸底，任何高度都不会互相压盖或溢出。
3. 弹窗 / 底部面板 / Toast 改挂到 `#overlay-root`，层级高于底部导航，不会再被导航条挡住点不到。


实测适配：`1280×720`、`1024×640`、`1440×900`、`430×900`（手机）下底部导航都完整可见。

## 9. 可落地性补强（从用户角度）

「页面能点」和「产品能用」之间还差几件事，下面几项已经做了：

| 用户会卡住的点 | 现在的做法 | 代码位置 |
| --- | --- | --- |
| **刷新就全没了**（最致命） | 记录与设置写入 `localStorage`，刷新 / 关浏览器都还在；隐私模式下自动降级为纯内存不报错 | `store/journal.js` |
| **识别不准就没有出路** | 拍照页新增「识别不准？手动记一餐」，直接进编辑页手填；没有照片时用虚线贴纸占位而不是破图 | `CameraView.vue` / `EditView.vue` / `SSticker.vue` |
| **记错了只能认命** | 首页卡片右上角「⋯」→ 编辑 / 删除；删除即时生效并提示 | `HomeView.vue` |
| **热量数字带来压力**（违背产品定位） | 「我的 → 无压力模式」：全站隐藏热量，只显示「已记录 N 餐」，进度条也收起 | `settings.hideKcal`，影响首页/周报/Sushie |
| **数据是不是被拿走了** | 数据只在本机，可一键导出 JSON / 复制为文本 / 清空 | `ProfileView.vue` |
| **贴纸只能留在 App 里**（小红书真实用户反馈「单独的贴纸能下载吗」→ 官方做不到） | 贴纸信息页「⤓ 存成贴纸图片」：Canvas 合成 540×640 PNG（白描边圆 + 名称 + 备注 + 水印）直接下载 | `utils/exportSticker.js` |
| **相册图刷新后消失** | 上传图先压到 900px、转 JPEG dataURL 再存，避免 blob URL 失效和 localStorage 撑爆 | `CameraView.vue` 的 `readImage()` |

### 还没做的（后续路线，答辩可讲）

1. **真识别与真 AI**：接一个识图接口 + LLM，`reply()` 换成 `fetch`，加载态用「Sushie 正在输入…」。
2. **账号与云同步**：现在换设备就没了；需要登录 + 增量同步 + 冲突策略。
3. **真提醒**：用餐提醒目前只是开关，实际要接 Notification API / Service Worker。
4. **搜索与筛选**：记录攒到几百条后只能翻，需要按名称/日期/餐段检索。
5. **PWA**：加 manifest + Service Worker，才能"添加到主屏 / 断网可用"。
6. **无障碍与埋点**：键盘焦点顺序、`aria` 已做基础，但还没有真实用户行为埋点和反馈入口。

## 11. AI 接入（看图识别 + 文字生成）

`npm run dev` 就能用，不需要配任何东西。

**分工（三层降级）**

| 能力 | 谁来做 | 说明 |
| --- | --- | --- |
| 看图认出是什么菜 | **CLIP（浏览器本地推理）** | 真模型、真看图，首次要下 146MB 权重 |
| 把这一餐写成一句手账备注 | **DeepSeek**（`deepseek-flash`） | key 写在 `server/aiConfig.js` |
| Sushie 的追问 | **DeepSeek**，带这一餐 + 今日摄入的上下文 | |

> ⚠️ DeepSeek 只有文本模型（实测传图会被拒），所以「看」和「说」是拆开的。
> 另外这把 key 直连写在代码里，只适合课程演示，正式项目请改成环境变量并轮换。

### 看图识别怎么做的

`src/utils/localVision.js` + `src/data/dishes.js`：

1. `Xenova/clip-vit-base-patch32`（q8 量化，约 146MB）在浏览器里跑，把图片编码成向量
2. 跟 `dishes.js` 里 20 道菜的英文描述比相似度，取最像的一道
3. 菜名 / 热量 / 六大营养素来自同一张表，所以识别出来的数字和菜名是对得上的

**实测**（工程自带的三张图，20 道候选）：鸭腿饭 / 番茄鸡蛋面 / 拿铁，全部 top-1 正确。

**耗时**（实测，会受机器影响）：

| 场景 | 耗时 |
| --- | --- |
| 首次下载模型 | 60–90s（界面显示百分比；进相机页就开始预下载） |
| 模型已缓存，单张识别 | 2–3.5s |

每条候选标签约 0.13s，所以只留了 20 道最常见的菜——想要更多菜就得接受更慢。

**限制**：只能认 `dishes.js` 里列出的菜；首次加载要等下载（F12 → Application → Cache Storage 可以看到缓存）。

### 模型从哪儿下

huggingface.co 国内连不上，hf-mirror.com 能下但不给 CORS 头，
所以 dev server 挂了一个 `/api/model/*` 代理（只放行 `Xenova/` 开头的仓库）：

```bash
# 换镜像源
AI_MODEL_MIRROR=https://hf-mirror.com
```

### 接口（都在 dev server 中间件，key 不进前端包）

| 接口 | 用途 |
| --- | --- |
| `POST /api/recognize` | 服务端视觉模型（配了 `AI_VISION_*` 才有）；没有就返回 `no-vision`，前端转本地 CLIP |
| `POST /api/ai` | `{task:'note'}` 写备注 / `{task:'ask'}` 回答追问 |
| `GET /api/model/*` | 模型权重代理，绕开 CORS 和网络问题 |

### 降级策略

任何一层失败（没 key / 超时 / 断网 / 模型加载失败）都会往下掉一级，
最差回落到 `data/mock.js`，页面照常跑。贴纸页会写清楚这次是
「AI 已识别」「本地模型识别」还是「本地估算」，不假装。

### key 放在 `.env`，不要写进代码

`server/aiConfig.js` 只从 `process.env.AI_API_KEY` 读，仓库里没有明文 key。
新机器上要启用 AI：`copy .env.example .env`，再填 `AI_API_KEY`。

> 踩过的坑：`vite.config.js` 里 `import { aiServer } from './server/ai.js'` 是**顶层静态导入**，
> 会在 `loadEnv()` 之前执行。所以 `AI` 对象的每个字段都写成 **getter**，
> 否则 `apiKey` 会被固化成 import 那一刻的空串，`.env` 里填了也永远是 `no-key`。

## 11. 部署成固定网址

完整步骤见 [`部署说明.md`](./部署说明.md)，这里只给结论：

| 方案 | 地址形态 | AI 能否真跑 | 适合 |
| --- | --- | --- | --- |
| **GitHub Pages**（仓库已配好 `.github/workflows/deploy.yml`） | `https://<用户名>.github.io/sushine/` | ❌ 无后端，降级为本地估算 | 交作业、扫码给别人看 |
| **Vercel** | `https://sushine-xxx.vercel.app` | ✅ 需把 `server/ai.js` 拆成 Serverless 函数 | 想要线上功能完整 |

之所以「推上去就能跑」，靠的是两件事：`base: './'`（产物全是相对路径，能放在任意子路径）
+ hash 路由（刷新任何页面都不会 404）。
